## 🔍 Детальний перелік зауважень та рекомендацій

### 1. Безпека та бізнес-логіка (High Priority)

#### ✅ [ВИПРАВЛЕНО] Потенційна розбіжність при перевірці OTP кодів по телефону
* **Виправлення:** Ендпоінт `/api/auth/send-verification-sms` тепер використовує хелпер `normalize_phone` для нормалізації номера перед збереженням OTP в базу даних. Це гарантує повну сумісність з етапом авторизації/реєстрації, незалежно від формату вводу користувачем.

#### 🚨 Небезпечний CORS (`allow_origins=["*"]`)
* **Проблема:** Дозволено підключення будь-яких доменів до API. Це підвищує ризик CSRF-атак.
* **Рішення:** Обмежити дозволені джерела через змінні оточення (наприклад, дозволяти тільки `frontend_url` з `.env`).

---

### 2. Архітектура бази даних та бэкенда (Medium Priority)

#### ✅ [ВИПРАВЛЕНО] Ручні SQL-міграції в `backend/main.py`
* **Виправлення:** Впроваджено офіційний інструмент міграцій **Alembic**. Всі ручні запити `ALTER TABLE` та супутній код перевірки колонок успішно видалено з `backend/main.py`. Створено початкову схему міграцій, а існуючу базу даних стамповано до версії `head`.

#### 📦 SQLite як єдина БД
* **Проблема:** SQLite підходить для розробки, але не підтримує високу конкурентність при великій кількості волонтерів і координаторів.
* **Рішення:** Налаштувати бэкенд на роботу з **PostgreSQL** за допомогою змінної `DATABASE_URL` у `.env` файлі для продакшну.

---

### 3. Архітектура фронтенду (Medium Priority)

#### ✅ [ВИПРАВЛЕНО] Розмір та складність `src/App.jsx`
* **Виправлення:** Впроваджено **Zustand** стейт-менеджер (`src/store/useStore.js`) для делегування всього глобального стану і бізнес-логіки. Для зручності користувача додано клієнтський роутинг через **React Router** (`HashRouter`), що повністю позбавило додаток від ручного перемикання екранів, забезпечивши підтримку кнопки «Назад» у браузері та можливість копіювання посилань на конкретні сторінки.
